# Как вносить изменения

Этот файл показывается в репозиториях организации, у которых нет своего CONTRIBUTING.

1. Изменения — в отдельной ветке, в `main` — через pull request.
2. Заголовок PR в формате [Conventional Commits](https://www.conventionalcommits.org/): `feat(export): add WebM output`, `fix(readme): correct install path`.
3. В описании PR: что меняется, как проверяли, пример «до / после» для изменений поведения.
4. Ревью у владельца репозитория до слияния. Сливаем через squash.
5. Людям изменения приходят после релиза с тегом и обновления тега в каталоге студии.
6. Исправили чужой инструмент — 30 дней после релиза помогаете с ошибками от вашего изменения. Так владельцу не страшно принимать правки.

Подробные правила, каталог и публикация — в [relatetest/hub](https://github.com/relatetest/hub) (доступен участникам организации).
